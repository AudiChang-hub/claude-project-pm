# 實作計畫：v1.1（T-40、T-42、T-43、T-44）

依據：[v1-core.md](v1-core.md) 第 2.4、3.7、8 節 ②，以及 PM 交辦的四項。從 v1.0.0（`main` 的 b6487e3）開始，只在本機 commit，不 push、不打 tag；版號由 PM 推版時決定（預計 1.1.0），CHANGELOG 先寫在 `Unreleased`。

## 共同做法

- 開發準則照舊：修 bug 先寫重現測試；測試失敗就改程式，不改測試，改既有測試要逐項寫理由（寫在 commit 訊息和最後的報告）；一個 commit 只做一件事；路徑一律經過 `plainLocalPath`；Windows 上啟動外部程式一律用完整路徑（`core/src/host.ts` 的 `run`）；不放寬任何安全檢查。
- 每個里程碑結束：core 的 `npm test`、`npm run typecheck`，`claude plugin test .`，`claude plugin validate .`，都看 exit code，全過才 commit。
- 示範和測試資料一律用 Acme，資料路徑用 `PROJECT_PM_HOME` 和暫存的家目錄，不碰使用者真正的 `~/.project-pm/`、`~/.claude/project-pm/`、`~/.claude.json`、`~/.claude/settings.json`。
- 會輸出文字的測試，中英文各跑一次。

## 實作前查證的事實（2026-11-21，Claude 桌面版 6.6395.0、Claude Code 2.1.326）

- 桌面版啟動的 `claude.exe` 帶環境變數 `CLAUDE_CODE_HOST_SESSION_ID=local_…`（就是 mod 從 `get_session` 拿到的 id）、`CLAUDE_CODE_ENTRYPOINT=claude-desktop`、`CLAUDE_CODE_SESSION_ID=<CLI 的 Session id>`。在這個 Session 的 Bash 子行程實際看到。MCP server 和 hook 也是 `claude.exe` 的子行程，會繼承同一份環境（v1.0 已實測 MCP 子行程有 `CLAUDE_CODE_SESSION_ID`）；桌面版的 MCP 子行程本身沒有實測，見 M3 的「沒驗證到的」。
- mod 的 `$.fs` 只有 `read`、`write`、`list`、`exists`、`stat`、`ancestors`：沒有刪除、改名、獨佔建立，做不到核心的「鎖 → 暫存檔 → rename」。

## 設計決定（T-40）

設計文件 2.4 節的 E2 寫「mod 透過核心的純函式讀寫新路徑，也照樣寫回舊路徑」。上面第二點使得 mod 自己寫新路徑時不能加鎖、也不是原子寫入：核心讀到寫到一半的檔會當成資料損毀（`StoreError`），而且依規定不會覆蓋它，看板會一直壞到有人修。所以分成讀和寫：

| | 做法 | 理由 |
| --- | --- | --- |
| mod 讀 | 新路徑和舊路徑都讀，用核心的純函式 `mergeLegacy` 合併（從 `core/src/store.ts` 抽成不碰 Node 的 `core/src/merge.ts`） | 和核心看到的一模一樣 |
| mod 寫（有核心） | 交給核心：`$.mcp.call('project-pm', …)`。認領、卸任用 `pm` 工具。提示列的「不要 PM」照舊寫舊路徑（只是一個旗標，核心讀取時依「後寫的為準」合併，不需要為它在模型看得到的 `pm` 工具加一個動作） | 鎖、合併、雙寫都在核心做，只有一份程式 |
| mod 寫（沒有核心，或呼叫失敗） | 照 v1.0 寫舊路徑 | 核心讀取時本來就會合併舊路徑（E1，已有測試），不會遺失 |
| 遷移 | 自動：核心第一次寫入時，新路徑就由「新＋舊」合併而來；沒裝核心的使用者資料留在舊路徑，裝了核心後直接讀得到 | 不需要使用者做任何事 |
| 回切 | 核心每次寫入都把完整內容寫回舊路徑（E1 雙寫），所以退回 v1.0 的 mod 或移除核心，舊路徑仍完整 | 2.4 節 |

其他：

- **偵測核心**（3.7 節）：mod 讀 Claude Code 的 MCP 設定（`~/.claude.json` 使用者層級的 `mcpServers`，以及這個專案的 local 設定），有 `project-pm` 就是「有核心」；Session 中途才連上的，也以工具清單裡有 `mcp__project-pm__pm`（只有核心有 `pm`）為準。
- **身分**：核心在桌面版用 `CLAUDE_CODE_HOST_SESSION_ID`（`local_…`）當 actor id，所以核心記的 PM、負責人、驗收者和 mod 是同一個 id，舊資料不用改。mod 另外把 `claude-code:<自己的 transcript id>` 也認成自己，萬一 MCP 子行程沒拿到 `local_…` 也不會認不出 PM。
- **Session 清單**（3.2 節「桌面版給 list_sessions」）：mod 本來就把每輪結果存在 `~/.claude/project-pm/rounds/<id>.json`（Session 清單、最後一句話、CI、push）。核心的看板在 PM 是桌面版 Session 時讀 PM 的 round 檔和舊路徑的 `sessions/<id>.json`，並合併核心 actor 裡同一個 id 的回報。mod 在模型呼叫 board、結案前先更新一輪，再讓核心回答，所以看板不會舊。round 檔超過 10 分鐘沒更新（桌面版沒開），就不再當成有人在執行。
- **hook 不重複**：桌面版有 mod 時，核心的 Claude Code hook 讓位（mod 已經用 `prompt.compose` 放交付指示和準則、記任務清單）；CLI 照舊由核心的 hook 處理。mod 在沒有桌面版 Session id 的地方（CLI）而且有核心時，也不再放交付指示，交給核心的 hook。
- **Agent 只能讀 ledger**：mod 照樣攔 PM 的 Agent 呼叫 `ledger` 的 add、update；其他交給核心。
- **init**：v1.1 起裝了 mod 也照樣加 MCP 設定和 hook（3.7 節：E2 之後不會撞名）。

## 里程碑

### M1 T-40：拿掉多平台程式，init 改寫進 CLAUDE.md

- `init` 把 project-pm 段落直接寫進專案的 `CLAUDE.md`（沒有就建立），不再寫 `AGENTS.md`、不再在 `CLAUDE.md` 加 `@AGENTS.md`。
- 拿掉 Codex 的 28 KiB 上限、精簡版段落、`init.agentsLong`（`core/src/install.ts:30-31`、`:95`），以及 codex 註解（`core/src/context.ts:14`、`core/src/types.ts:38`）。段落本身 2 KiB 的上限保留。
- 舊安裝：重跑 `init` 時，依 `install-log.json` 把 v1.0 寫進 `AGENTS.md` 的段落拿掉（和 uninstall 同一套還原），`CLAUDE.md` 的 `@AGENTS.md` 那一行換成段落本身；`uninstall` 照紀錄完整還原 v1.0 寫過的 `AGENTS.md` 和 `CLAUDE.md`。

驗收條件：

1. 新安裝：`init` 後 `CLAUDE.md` 有段落、沒有 `AGENTS.md`；`uninstall` 後每個檔和安裝前逐位元相同（沒有 `CLAUDE.md`、已有 `CLAUDE.md`（含 CRLF）、已有自己的 `AGENTS.md` 三種）。
2. v1.0 的舊安裝（用 v1.0 的寫法造出 `install-log.json`、`AGENTS.md`、`CLAUDE.md`）：直接 `uninstall` 完整還原；先重跑 v1.1 的 `init` 再 `uninstall` 也完整還原。
3. 程式和測試裡沒有 `AGENTS_LIMIT`、28 KiB、codex 註解。

### M2 T-40：核心認得桌面版 Session

- 身分：MCP 連線和 hook 在 `CLAUDE_CODE_HOST_SESSION_ID` 是 `local_…` 時用它。
- 看板和結案檢查的 Session 來源：PM 是桌面版 Session 時，讀它的 round 檔和舊路徑的 Session 檔，並合併同 id 的核心 actor（回報）；PM 的 Agent 紀錄也從舊路徑讀。
- 核心的 hook 在桌面版、mod 已安裝時讓位。

驗收條件：

1. 有 `CLAUDE_CODE_HOST_SESSION_ID=local_x` 時，MCP 的 `pm claim` 記下 `local_x`；hook 寫的 actor 也是 `local_x`；沒有時和 v1.0 相同。
2. 用 Acme 的 round 檔和 Session 檔：核心的 board 列出桌面版的 Session 和狀態（含「等你回覆」「CI 失敗」），文字和 mod 自己畫的一致；結案檢查用得到 round 的最後一句話；round 過期時不算執行中。
3. 桌面版＋mod：hook 不寫 actor、不輸出任何東西；CLI：和 v1.0 相同。

### M3 T-40：mod 改用核心

- 偵測核心（上面「偵測核心」）。有核心時不註冊 board、ledger、report，攔到這三個工具時先更新一輪再交給核心回答（Agent 改 ledger 照樣擋）。
- 讀專案：新路徑＋舊路徑，用 `mergeLegacy`。寫：有核心時經核心，否則（或失敗時）寫舊路徑。
- Session 卡片讀得到核心 actor 的回報（模型用核心的 `report` 回報時）。
- 沒有核心時，行為和 v1.0 完全相同。
- `init`：裝的 mod 是 1.1 以上（依版本號判斷，2.4 節）時也加 MCP 設定和 hook；更舊的 mod 照 v1.0 不加，並提示更新。
- mod 在用核心時，每 4 分鐘至少重寫一次 round 檔（內容沒變也寫），核心才不會把它當成桌面版已關閉；沒有核心時照舊只在內容變了才寫。

驗收條件：

1. 原有的 `claude plugin test .` 測試全過（沒有核心的情況）。
2. 有核心時：mod 不呼叫 `tool.register`；`/pm` 經 `pm claim`、`/pm off` 經 `pm release`；呼叫失敗時寫舊路徑。
3. 雙寫不遺失（並列測試，用核心的程式和 mod 的寫法輪流寫同一個專案）：核心寫 → mod 讀得到核心欄位（`uid`、`rev`、`commits`、`qa.byPerson`）；mod（v1.0 寫法，寫舊路徑）寫 → 核心讀得到、核心欄位補回；交替 20 次後每一項的每個欄位都在。
4. 回切：上面的流程之後，舊路徑的檔單獨拿出來，v1.0 的 mod 讀得到每一項（舊格式的欄位都在）。

### M4 T-42 面板摘要的數字要加得起來

- 一個純函式把每個進行中的項目只歸到一類，順序是「QA 不通過 → 待 QA → 未指派 → 正常」，放在 `hooks/qa.ts`，面板、文字看板、網頁看板共用。
- 面板：「4 項進行中：1 項 QA 不通過・1 項待 QA・1 項未指派・1 項正常」，數字是 0 的類別不列。
- 文字看板在進度那一行下面加同一句；網頁看板的 JSON 多一個 `breakdown`，畫面上同一句。

驗收條件：

1. 單元測試：同一項有多種狀況（未指派又 QA 不通過）只算一次、全部正常、全部有狀況；各類加總等於進行中的數量。中英文各一。
2. 面板、文字看板、網頁看板用同一個函式、同一句話（測試比對三者的字串）。

### M5 T-43 不顯示原始 Session id

- 一個純函式給 Session 的可讀名稱：Session 標題 → report 的 `title` → 第一則指示的摘要 → 縮短的 id（`claude-code:6f1d3b2a…` 寫成 `6f1d3b2a`）。面板、文字看板、網頁看板共用。
- 網頁看板：PM、負責人、需要處理、Session 卡片都只顯示名稱。
- 文字看板是給模型讀的：名稱照新規則，但保留 id，因為 PM 指派負責人（`owner`）時要用它。面板本來就不顯示 id。
- 跳脫：網頁看板一律用 `textContent`。

驗收條件：

1. 單元測試：四種來源的優先順序、縮短的 id。
2. XSS：標題、回報、工作項目含 `<img src=x onerror=…>`、`</script>`、`"'&` 時，`/api/board` 原樣回傳文字；實際用 headless Edge／Chrome 打開網頁看板，DOM 裡沒有多出任何元素、`onerror` 沒有執行、畫面顯示原文；`app.js` 沒有 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`（靜態檢查）。沒有瀏覽器的環境略過瀏覽器那一項並寫明。
3. 網頁看板的 JSON 和畫面上沒有 `claude-code:` 開頭的完整 id。

### M6 T-44 網頁看板和桌面面板視覺統一

- 狀態色和語意用面板的同一組（`hooks/sessions.ts` 的 `STATUS`）：網頁看板從 JSON 拿到狀態，顏色由同一份色票產生；深色另調亮度，維持 WCAG AA。
- 摘要：完成度環、執行中／待回覆／尚未完成三個數字（算法和面板相同，由核心算好放進 JSON）、M4 的那一句。
- 工作項目：代號、內容、負責人（名稱・狀態）、QA。Session 卡片：狀態點（執行中會脈動）、名稱、時間、狀態・步驟、步驟條、目前步驟、摘要或待辦。Agent 卡片：菱形。
- 維持寬版：寬螢幕兩欄（左：需要處理、工作項目；右：Session、Agent），窄螢幕一欄，375px 不水平捲動。
- 淺色、深色、跟隨系統；`prefers-reduced-motion` 時不脈動、不過場。

驗收條件：

1. 在瀏覽器實際打開（Acme 假資料）：375px、768px、1280px、1600px；淺色、深色；空狀態、錯誤狀態、載入中都看過；修好看到的問題。
2. 文字和狀態色的對比 ≥ 4.5:1（小字）／3:1（大字、圖形），淺深兩種都算過並寫在報告。
3. 既有的安全測試（token、Host、Origin、CSP）全過；CSP 不放寬。
